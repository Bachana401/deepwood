# HOW TO HIRE A DEPARTMENT

Open a new Claude Code session in `C:\Users\bacho\Documents\deepwood` and send it
exactly one line:

```
Read STUDIO_BRIEFS/<department>.md and STUDIO.md, then do the job.
```

That is the whole hiring process. The brief is self-contained: it carries the
territory, the house rules, the method and the definition of done, so the new
session needs nothing from the conversation it came from.

## Open positions

| Send it | Department | The job |
|---|---|---|
| `STUDIO_BRIEFS/writing.md` | **Writing** | The village's new systems announce themselves in flat status-line English. Give sickness, fire, patrols and the eclipse a voice. |
| `STUDIO_BRIEFS/qa.md` | **QA** | The test registry is static — an unregistered test never runs and the suite still says ALL PASS. Close that hole and find every test that is lying. |
| `STUDIO_BRIEFS/scenes.md` | **Scenes** | The dev's complaint: the building chain is *"invisible / numbers not feel."* Make the settlement's machinery something you can see standing in it. |
| `STUDIO_BRIEFS/balance.md` | **Balance** | Nobody has pointed the marathon sim at the new village economy. Find where the curve lies to the player. |

## The two rules that make this work

1. **Territory.** Two employees never own the same file. `STUDIO.md` has the map.
   A department that needs a change in someone else's file writes the exact patch
   into its report; the owner applies it. This is the single rule that keeps the
   team from spending all its time merging.
2. **Everything routes through the lead.** Departments do not talk to each other
   and do not merge each other's work.
